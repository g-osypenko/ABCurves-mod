# ABCurves Closed-Loop Refactor — Status

> Живой статус рефакторинга: что сделано, чем доказано, что осталось. Полный

## Цель (кратко)
Превратить ABCurves в замкнутый Receding-Horizon генератор траекторий для слежения
за движущейся целью, убрав нестабильный `_continuous` FSM и сохранив человечность
движения. Цели владельца: **стабильность, без нервозности, точность, убрать патологии**
исходных доков.

## Принятые решения
- **Подход Б (RHC + ProDMP + persistent GRU-рендерер)** — вместо эвристик вокруг TCN.
- **B2′** — forcing-веса (макро-кривизна) запекаются из `motor.onnx` **офлайн** в
  библиотеку, а не гоняются живьём. `motor.onnx` сохранён как bake-ассет; `_continuous`
  оставлен offline-only, рантайм от него изолирован. (см. [DESIGN_NOTE §3](DESIGN_NOTE.md))
- Координаты: **native mouse counts** (как у рендерера).

**Человечность (измерено):**
- Закон двух третей (step): β≈**0.39–0.45**, R²≈**0.72–0.88** (человек ~0.33).
- Texture19 (метод floors, 256 строк): within-human **0.17**, between-human **0.50**,
  **B1 = 0.88 (OUTSIDE)**, **B2′ = 0.42 (INSIDE человеческого диапазона)**. Макро-кривизна
  улучшает и текстуру. Контроль метода: наш within-floor 0.17 ≈ опубликованный same-session 0.15.

**P2 — forcing безопасен:**
- **Safety-потолок (всегда вкл):** `forcing_gain_max=0.6`. Любой запрошенный gain (до 2.5)
  сходится (resid **0.00**, 20 seeds). Корень нестабильности — положительная обратная связь по
  скорости (forcing раздувает переносимую `ydot_b`), а не разовый большой изгиб; потолок её гасит.
- **Adaptive back-off (дистанционный) реализован, но `forcing_adaptive=False` по умолчанию:**
  измерено, что он снижает круговой лаг (67→~50), но регрессирует текстуру reach
  (0.42→0.54), т.к. срезает кривизну у цели. Круговой лаг — не патология, а reach-текстура —
  главная метрика; поэтому рычаг припаркован до P4.
- Текстура при дефолте сохранена: **B2′ = 0.421 INSIDE**.

**P3 — текстура (2026-10-13):**
- **Методика исправлена.** Раньше все строки генерировались с одним `event_seed=7` — это
  льстило счёту (0.42/0.45). Честно (свой сид на строку) старая версия = **~0.52**. Кроме того,
  строки датасета начинаются *в движении* (точка B = 60% пути, скорость ~2–4 c/мс), а генератор
  стартовал из покоя → добавлен handoff `reset(initial_velocity=...)` (C¹-подхват курсора на лету;
  в оценщике скорость берётся из префикса — только офлайн). `tools/texture_eval.py` обновлён.
- **Диагноз.** Все топ-разрывы были в одну сторону: генератор «стерилен» (мало энергии
  10–200 Гц, нет редких нулей на высокой скорости). При этом рендерер *при одинаковой скорости*
  совпадает с человеком почти идеально → остаток = (а) микро-вариативность команды и
  (б) макро-профиль скорости (хвост «подползания»: 32–37% времени <0.25 c/мс против 20% у человека).
- **(а) Сигнал-зависимый моторный шум (Harris–Wolpert), ВКЛ по умолчанию** `motor_noise_rel=0.25`:
  мультипликативный, *вдоль* направления движения → ноль в покое (нет idle-джиттера), не меняет
  знак осей (изотропный вариант взрывал `sign_flip_rate` — отвергнут). Даёт **0.48 → 0.34** на
  отложенных строках, точность/плавность не тронуты (rms ±1%, LDLJ/SPARC те же). После него
  по-тиковая статистика совпадает с человеком (нули/модуль пакета по бинам скорости).
- **(б) Горизонт.** `horizon_ms` 250→320 даёт ещё **0.34 → 0.27** (на 256 отложенных строках
  0.254–0.279), но **ухудшает pursuit-точность на ~20%** (круг rms 67→81). Точность — явная цель,
  поэтому дефолт оставлен **250**; 320 — документированная «reach-текстурная» настройка.
  Развязка (получить оба) → P4. **→ Снято в P4: упреждение убрало лаг, дефолт теперь 320.**
- **Fitts time-to-go горизонт (Hoff–Arbib)** `horizon_fitts_b>0`, по умолчанию ВЫКЛ: убирает
  хвост (`zero_rate`↓), но короткий горизонт у цели даёт микро-колебание (разброс `sign_flip_rate`)
  = нервозность. Рычаг припаркован для P4.
- Отвергнуто измерением: разброс точки прицеливания по Фиттсу (σ=R/2.07) — на текстуру не влияет.
- **Итог (официальный `texture_eval.py --rows 256`, честная методика): B2′ = 0.351 INSIDE**
  (within 0.17, between 0.50); B1 = 0.89. Оставшиеся топ-разрывы — `iri_p95`, `zero_run_mean`,
  `zero_rate` = именно макро-хвост.

**P4 — ядро (2026-10-13): текстура И точность одновременно.**
Конфликт P3 (горизонт 320 = человечная текстура, но +20% pursuit-лага) снят **упреждением по
скорости цели** (predictive pursuit): план наводится туда, где цель *будет* через
`ff_lead_frac·tau`. Абсолютная позиция цели = собственный курсор (сумма отчётов, точно) + ошибка.
- Оценщик скорости `target_ff`: **`alpha_beta` (дефолт, α=0.5 β=0.2)** — установившийся Калман,
  ~10 flops на обновление (+~20 мкс, в шуме замера); `raw` (Δx/Δt) — опция, на ~10% точнее,
  но **проваливает гейт дрожания цели** (jitRms 1.32 > 1.3 — патология #3), поэтому не дефолт.
  Гейт по невязке (`ff_gate=40`): прыжок цели = переинициализация, а не фантомная скорость.
- **Фикс коммита:** при обновлениях реже `commit_ms` (напр. 16 мс при commit 12) рендерер
  простаивал 4 мс из 16 → лаг и лишние нули. Теперь коммит ≥ `dt+2`. Один этот фикс: pursuit 37.5→30.
  После него оптимум упреждения одинаков для 8 и 16 мс: **0.3·tau** → `ff_lead_frac=0.3`.
- **Ускорение перепланирования ×3.4** (1029→~300 мкс): `ProDMP._basis_at` интерполировал 42
  столбца в питоновском цикле → векторизовано (результат идентичен, закреплено тестом).
  Итог: секунда движения ≈ 57 мс CPU (~6% ядра): replan ~300 мкс ×125/с + step ~20 мкс ×1000/с.
